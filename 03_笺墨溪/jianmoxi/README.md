# 笺墨溪

阅读、灵感、写作与 AI 搭子的私有项目。当前网页版入口：[笺墨溪 Web](https://49.234.43.25/web/index.html)。

- `cloud_app.py` 与相关 Python 模块：云端 API、登录、状态保存、书库和 AI 服务。
- `dist/`：线上业务前端；`dist/web/` 为桌面网页入口与布局，复用已有业务模块。
- `web-client/`：此前独立网页方案，保留作参考；当前桌面入口使用 `dist/web/`。
- `android/`：Android WebView 外壳；`deploy/`、`DEPLOYMENT.md`：服务配置与发布记录。

仓库包含截至 2026-11-08 的网页交互、启动加载及对话布局修复。运行数据库、部署凭据、访问密码、Android 签名及临时快照不纳入版本管理。云端部署与环境要求见 [DEPLOYMENT.md](DEPLOYMENT.md)，Python 依赖见 `requirements.txt`。

## 历史本地原型说明

本地、无构建依赖的响应式交互原型。使用现代书刊排版、暖白背景和摄影，支持手机与桌面布局。

## 启动

在本目录运行：

```sh
python3 server.py
```

访问 http://127.0.0.1:8765 。需要使用上述服务启动，它同时提供一言与 LRCLIB 的转接接口；普通静态服务器不能使用在线来源和 AI 功能。

## 页面与功能

- 灵感：带分类的分页列表，每页最多三条；呈现原文摘句、作者、篇名，支持查看出处、延伸灵感和收藏。已移除灵感页及详情内的立即写作按钮。
- 写作：正文编辑、本地自动保存、字号调整、完成状态、文本导出、DeepSeek 修改建议、实时续写与撤销插入。
- 文章：标题和正文搜索、草稿与已完成筛选、编辑、回收站与恢复。
- 阅读：顶部分类从本批推荐文章自动生成；收藏可独立切换，保留详情与读后感入口。
- 搭子：收敛为手稿与批注两个视图、邀请预览；不会向他人发送信息。
- 写作记录：真实本地编辑记录、当月日历、字数目标、批量导出。
- AI 助手：编辑页内真实建议与续写；独立聊天入口已移除。

## 边界

没有连接 APK 的云服务、账号或真实 AI。灵感已接入一言、LRCLIB，并导入康奈尔电影对白；阅读与搭子仍为演示，写作建议已接入 DeepSeek。编辑内容保存在当前浏览器 localStorage 中，不支持跨设备同步；清理浏览器数据会清除内容，请导出重要文字。

每日新增字数仅用于交互演示，并非独立创作量度量。现版本不包含登录、图片上传、真实逐篇分享与云端备份。初始文学示例已核对；在线来源的摘句尚未逐条核对。延伸灵感由 DeepSeek 生成，调用失败时明确退回预设提示，不将提示归为原作者的话。

## 第四轮：动态推荐与文章页精简

去掉文章页顶部的继续写作卡片，不新增替代模块；文章仍可从列表直接打开。
灵感与阅读的分类栏不再配置固定主题，而是从当前推荐内容去重生成，保留“全部”。换一批后若原分类消失，自动返回全部；收藏独立保留，阅读正文也缓存于本机，换批或刷新页面后仍能查看。

第四轮“换一批”在两组预设示例之间切换；第五轮已将灵感换成真实来源，阅读仍保留示例。两者都**不是实时 AI 生成或个性化推送**。`feed-provider.js` 保留演示适配器，可在 `refinements.js` 加载前设置 `window.xingzouFeedProvider` 为自定义适配器：

```js
// 在服务端保管模型密钥；不要在前端放入密钥。
window.xingzouFeedProvider = {
  async load({kind, cursor}) {
    // kind 为 inspiration 或 reading；首次 cursor 为 null。
    // 请求真实后端并返回 { items, nextCursor }。
  }
};
```

灵感条目字段：id、topic、img（现有素材键）、short、desc、questions、source（author、work、year、quote、url、note）。阅读条目字段：id、category、title、author、img、intro、body。来源字段缺失、数据格式异常时保留上一批并提示重试；服务端仍须核验引文是否真实，前端字段校验不等于事实核查。当前阅读详情的“演示原创”标识与素材键为原型约束，接入真实内容时需一并换成真实来源与图片字段。

浏览器验证：两页换批后分类与内容同步更新、选中主题失效后回到全部、新阅读收藏换批及刷新后可打开、原有文章完整保留。

## 第五轮：真实内容来源

- 一言：文学（d）、古诗文（i）、影视（h），每批各取一条；保留正文、署名、作品名和 UUID。文学条目可能包含流行小说，但接口没有小说与散文细分，所以不擅自标成“流行小说”。影视可能包含电视剧，独立于电影分类。
- LRCLIB：按内置的入门歌曲关键词轮换查询，过滤标题、制作信息及纯音乐，每批选取一行歌词。保留歌曲、歌手、专辑及记录 ID；词作者字段缺失时明确标注，不把歌手标成词作者。并非个性化推荐。
- Cornell Movie-Dialogs Corpus：从官方压缩包导入 120 条英文短对白，涉及 101 部电影。保留片名、年份、角色、电影 ID、对白 ID 和原始包校验值。自动筛选结果不是已经核实的上映字幕，也不是 AI 翻译。数据及原项目说明在 dist/data/。

`server.py` 只监听 127.0.0.1，转接两个指定的公开内容服务，不接受目标域名，不上传草稿或收藏。使用系统 curl 获取内容，带超时、缓存及一言请求节流。`dist/live-feed.js` 统一内容结构，单个来源失败时使用该来源上次成功内容并显示状态，其余来源可继续返回。收藏保存完整摘句与来源，换批后仍可打开。

列表保留文学风格，过长摘句在详情查看。作者、词作者或编剧未提供时如实标注；在线来源不再显示“原文已经核对”的固定声明，写作引导标注为预设提示。

验证：一言与 LRCLIB 通过本地转接返回真实内容；电影数据在浏览器中可加载。Python 四项检查覆盖端点白名单、参数编码、缓存和失败恢复；JavaScript 检查覆盖歌词标题行过滤、署名、部分来源失败和断网缓存。真实模型尚未接入。

浏览器走查通过：换批后电影与一言内容更新，歌词收藏换批后可回看；390×844 首屏无横向或纵向溢出。LRCLIB 查询期间出现过服务繁忙，转接会重试一次，仍失败则明确显示使用上次内容。截图：live-sources-preview.jpg。

官方说明：[一言](https://developer.hitokoto.cn/sentence/)、[LRCLIB](https://lrclib.net/docs)、[Cornell](https://www.cs.cornell.edu/~cristian/Cornell_Movie-Dialogs_Corpus.html)。来源公开可访问不代表本项目取得额外内容授权。


## 第六轮：DeepSeek 实时接入（当前）

在项目根目录的 `.env.local` 配置 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_MODEL`，格式见 `.env.example`。私有配置权限为 600，不在静态目录中，且由 `.gitignore` 排除。环境变量优先于文件。请勿将密钥写入 dist；每次请求重新读取配置，修改后无需重启。

按要求发送模型名 `deepseek-v4-flash`。当前官方将其路由到 V4.1-Flash-1017，实测响应模型字段为 `deepseek-flash`。采用非思考模式和 JSON 输出。

- 灵感：先从已有真实来源获取本批候选，再让 DeepSeek 排序并生成切入点与问题。后台只传候选原文、署名、作品和分类，不读取或发送用户草稿。模型只能返回已有 ID，来源对象不经模型覆盖。这是候选排序，尚不是根据个人写作习惯推荐。
- 写作：打开助手本身不上传正文，点击“给我修改建议”或“沿着这段续写”才提交当前文章；正文限制 12000 字。续写先预览，可插入、撤销；文章发生变化时拒绝插入旧结果。关闭弹窗停止前端等待，已送到模型的请求可能仍会处理。
- 失败：保留原文和来源，灵感明确显示预设回退，编辑器提供错误及重试按钮，不用固定文案假装模型结果。
- 服务：只监听本机，AI POST 校验同源与 JSON，输入限长、最多两项并发、上游超时。密钥和正文经 curl 标准输入发送，不在进程参数或 HTTP 日志中；对外错误不回显上游原始报文。
- 本地接口：GET `/api/ai/status`；POST `/api/ai/inspiration`、`/api/ai/advice`、`/api/ai/continue`。

真实调用已验证：本批灵感排序、中文写作提示、独立测试短文的修改建议与续写，浏览器完成插入和撤销，恢复测试原文。临时测试文章已移入回收站，原有五篇文章保留。390×844 灵感页无溢出，浏览器无脚本错误。10 项 Python 检查通过，覆盖原有内容转接、AI 输入与来源 ID 校验、错误脱敏、同源限制及私有配置不可下载。仍未部署云端；文章保存在浏览器，阅读和搭子仍为演示。
