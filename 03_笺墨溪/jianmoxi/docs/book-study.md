# 分层书库分析与语录库

入口：我的 → 语录库。API `/api/quotes?q=&workId=&page=1&limit=20`；进度 `/api/quotes/status`，均沿用登录权限。

`book_study.py` 在派生 `knowledge.db` 中维护版本化任务，不修改用户文稿、偏好或摘录。每章按 8000 字切成连续单元，附前后最多 500 字上下文；完整覆盖全部单元才形成章节归纳，最多 16 个子摘要一组递归汇总，最终形成全书归纳。单单元章节复用完整单元分析，避免不必要的重复模型调用。它是基于完整分段覆盖的分层分析，不是一次性把全书交给模型，也不保证文学判断绝对正确。

每单元最多提取 2 条 16–70 字候选。程序恢复可核验的原文标点，拒绝无法对应原文的候选；独立复核要求语境忠实、独立可读和文学价值均通过。具体实用建议、缺失人物前情、关键剧透不进入可用库。保留章节字符起止位置、原文版本、复核理由、情感主题与意象。去重与分页在 SQLite 内完成。

所有流转记录位于 `study_books / study_jobs / study_dependencies / study_quotes`。运行时有事务领取和 240 秒租约，异常按退避重试，最多 4 次后标记失败。父任务不能跨过未完成或失败的子任务。源版本变化时读接口立即排除旧分析和语录，下一轮规划重建该书；归档书籍不再提供。后台每小时检查新书与版本变化。

云端服务：`xingzou-book-study`，服务器重启后自动继续；两路模型任务并发，低 CPU 优先级。查看状态用 `systemctl status xingzou-book-study` 和 `journalctl -u xingzou-book-study`。管理时先停止服务，避免同一锁下启动第二个 supervisor。

手动规划：`scripts/study_library.py --db /var/lib/xingzou/app.db --plan --steps 10`。
派生库路径跟随 app.db 的同级 `knowledge.db`，运行用户必须与主服务一致，避免生成 root 所有的 WAL 文件。不要用测试数据库覆盖云端数据。

`library_knowledge.retrieve()` 为小溪补充已完成的章节和整书分析，明确实际覆盖范围；相关已审核语录帮助定位原文检索。现代文学候选自动进入灵感候选池，保留既有默认体裁限制与用户偏好；其他体裁仍可从完整语录库检索。图片仍由现有图库机制提供，本轮没有声称实现视觉模型配图。

验证：`python -m unittest test_book_study.StudyTests`，以及现有阅读、灵感、对话、云保存回归测试；`.deploy/book-study/client-check.cjs` 检查入口、搜索、空状态、原文定位与讨论上下文。手机视觉验收由用户完成。
